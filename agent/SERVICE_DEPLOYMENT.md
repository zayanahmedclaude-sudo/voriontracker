# Vorion Tracker Windows supervisor

Windows deployments use two processes:

- `VorionSupervisor.exe` is an SCM-aware LocalSystem service. It validates enrollment with the configured HTTPS backend before storing the device token using machine-scope DPAPI in an administrators/SYSTEM-only directory, launches the capture agent in the active console session, validates named-pipe clients by the PID it launched, and uses bounded exponential backoff when the child repeatedly exits or misses heartbeats.
- `Vorion Tracker.exe --supervised` is the interactive desktop capture process. It never runs in session 0.

The NSIS package is per-machine. Setup submits the Windows computer name as a pending request and waits for up to 15 minutes. An admin opens **Dashboard > Devices**, chooses the employee if applicable, and clicks **Approve**. The backend creates the permanent device token and encrypts it to the temporary RSA public key generated by that installer, so the credential is never displayed or copied. The supervisor decrypts it locally and stores the token and server with machine-scope DPAPI. Production uses `https://api.vorionsystems.com`; use `http://localhost:3000` only when testing both sides locally.

Install through the deployment script from an elevated shell:

```powershell
Start-Process .\VorionTrackerSetup.exe
```

The sanctioned stop and uninstall entry points show UAC when they are not already elevated:

```powershell
& "$env:ProgramFiles\Vorion Tracker\resources\VorionSupervisor.exe" --stop
& "$env:ProgramFiles\Vorion Tracker\resources\VorionSupervisor.exe" --uninstall
```

Capture continues for a 20-second grace period after a lock event, pauses if the session remains locked, and resumes immediately on unlock. No capture is attempted without an interactive Windows session.

Screenshots are written before upload to `%ProgramData%\VorionTracker\secure\screenshot-queue`. Each record is protected with machine-scope DPAPI, and the directory ACL grants access only to LocalSystem and administrators. The queue retains transient failures across process and machine restarts, removes a record only after an idempotent backend commit, and quarantines permanent commit rejections. It accepts at most 2,000 records, 12 MiB per record, and 1 GiB total. At quota, new captures are rejected and existing evidence is retained.
